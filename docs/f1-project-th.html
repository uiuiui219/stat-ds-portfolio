1 · โจทย์และวัตถุประสงค์ Research question

โจทย์: จำแนกแบบสองกลุ่ม (binary classification) ว่านักขับคนหนึ่งจะได้คะแนนในเรซนั้นหรือไม่ — คะแนนในการแข่งขันฟอร์มูล่าวันมอบให้ผู้จบอันดับ 1 ถึง 10

หน่วยวิเคราะห์: หนึ่งแถวคือผลของนักขับหนึ่งคนในหนึ่งเรซ (race entry) ตั้งแต่ปี 2019 ถึง 2024 รวม 2,559 race entries

วัตถุประสงค์: (1) จำแนกและจัดกลุ่มสนามแข่งขันตามลักษณะเฉพาะของสนาม (2) เปรียบเทียบประสิทธิภาพของตัวแบบการพยากรณ์การได้คะแนนของนักขับในแต่ละรอบการแข่งขัน และ (3) วิเคราะห์และอธิบายความสำคัญของปัจจัยที่ส่งผลต่อการได้คะแนนของนักขับ

ข้อมูลนำเข้า: เฉพาะข้อมูลที่มีก่อนการแข่งขัน ได้แก่ ประวัตินักขับและทีม ตำแหน่งออกสตาร์ท ลักษณะของสนาม และสภาพอากาศวันแข่ง

2 · ข้อมูล Data

แหล่งข้อมูลให้ข้อมูลอะไร
Ergast F1 API ผลการแข่งขัน ตำแหน่งออกสตาร์ท พิตสต็อป เวลาต่อรอบ คะแนนสะสม และสถานะการจบการแข่งขัน — เก็บเป็นไฟล์บีบอัดที่ data/ergast-f1-data.zip
Open-Meteo อุณหภูมิ ปริมาณฝน และลมรายชั่วโมงของแต่ละสนาม ดึงย้อนหลังในหน้าต่าง ±3 วันรอบเวลาแข่ง ไฟล์ตัวอย่างบางเรซถูกเก็บไว้ในรีโป และมีสคริปต์สร้างตารางเต็มขึ้นใหม่ได้
Pirelli Motorsport ลักษณะเฉพาะของสนาม เช่น tyre stress, lateral load, grip, downforce ความยาวสนาม และจำนวนโค้ง หลังกรองเหลือ 128 สนาม ที่ใช้ในการจัดกลุ่ม
ตารางเวลาแข่ง วันและเวลาของการแข่ง ใช้จัดหน้าต่างเวลาให้ตรงกับสภาพอากาศ

การเชื่อมข้อมูลอากาศ: หน้าต่างเวลาที่ใช้คือระยะเวลาการแข่งขันจริง ซึ่งคำนวณจากเวลารวมของนักขับที่ชนะ (จากไฟล์ lap_times) นับจากเวลาเริ่มแข่ง แล้วหาค่าเฉลี่ยสภาพอากาศในช่วงนั้น ไม่ได้ใช้ค่าเฉลี่ยของทั้งวัน

ข้อมูลดิบขนาดใหญ่ไม่ได้ commit ลงรีโป README ของโปรเจกต์ระบุแหล่งดาวน์โหลด และ code/build_weather_circuit.R สร้างตารางอากาศขึ้นใหม่ได้ (ใช้เวลาประมาณ 3 นาทีและต้องต่อเครือข่าย)

3 · ตัวแปรและการป้องกัน data leakage Features

ตัวแปรแบ่งเป็น 6 กลุ่ม ได้แก่ ข้อมูลพื้นฐานของนักขับและทีม ประสบการณ์และผลการแข่งขัน ข้อมูลการแข่ง สภาพอากาศและบริบทการแข่ง ลักษณะทางกายภาพของสนาม และลักษณะทางเทคนิคของสนาม

ตัวแปรข้อมูลนี้รู้ได้ก่อนการแข่งอย่างไร
Ageอายุจากวันเกิดถึงวันแข่ง
Driver_Experienceจำนวนเรซที่นักขับลงแข่งก่อนเรซนี้ (row_number() - 1 ต่อนักขับ เรียงตามฤดูกาล)
Driver_Podiumจำนวนโพเดียมสะสม ก่อน เรซนี้ — lag(cumsum(positionOrder %in% 1:3))
Prev_Total_Pointsคะแนนสะสมก่อนหน้า โดยเลื่อนค่าถอยหลังหนึ่งเรซ (lag) เพื่อไม่ให้ผลของเรซปัจจุบันปนเข้ามา
Constructor_Winsจำนวนชัยชนะสะสมของทีมก่อนเรซนี้
Constructor_DNF_Scoreจำนวนการไม่จบการแข่งขัน (DNF) สะสมของทีมก่อนเรซนี้
avg_temperature, avg_rain, avg_wind_speedค่าเฉลี่ยสภาพอากาศในช่วงเวลาแข่ง
clusterหมายเลขกลุ่มของสนามจากขั้นตอนการจัดกลุ่ม
gridตำแหน่งออกสตาร์ท ซึ่งทราบหลังรอบคัดเลือกและก่อนการแข่ง มีอยู่ใน data/final_table_with_cluster.csv และในสคริปต์ v1 / v2 ส่วนตัวอย่าง Random Forest ใน Rmd ตัดตัวแปรนี้ออก
หลักการป้องกัน leakage ที่ใช้ในโค้ด
ตัวแปรสะสมทั้งหมดถูกเลื่อนถอยหลัง (lag) ก่อนเรซปัจจุบัน เพื่อไม่ให้เรซที่กำลังทำนายส่งผลต่อตัวพยากรณ์ของตัวเอง ตัวแปรอัตราที่คำนวณจากการแข่ง เช่น Overtake_Rate ใช้เฉพาะเรซก่อนหน้า DNF_flag สร้างจากสถานะการจบการแข่งขันของเรซก่อนหน้า ซึ่งเป็นข้อมูลหลังแข่งแต่เกิดก่อนเรซที่กำลังทำนาย

4 · การจัดกลุ่มสนามแข่งขัน Circuit clustering

  1. สร้างตารางรายสนาม: ตัวแปรจาก Pirelli (จำนวนโค้ง ระยะทาง ความยาว tyre stress, lateral load, downforce, asphalt grip และ abrasion) รวมกับอัตราที่คำนวณจากการแข่งจริงจาก Ergast (Overtake_Rate, Race_DNF_Rate)
  2. ตรวจความเหมาะสม: ค่า KMO และโครงสร้างสหสัมพันธ์ระหว่างตัวแปร
  3. ลดมิติ: ใช้ PCA โดยเลือกจำนวนองค์ประกอบจากสัดส่วนความแปรปรวนสะสม
  4. จัดกลุ่ม: daisy(..., metric = "gower") → hclust(..., method = "complete") และเลือกจำนวนกลุ่มด้วยดัชนีคุณภาพการแบ่งกลุ่ม ซึ่งรวมค่า average silhouette width รายงานฉบับจบได้ 5 กลุ่ม จาก 128 สนาม
  5. เชื่อมกลับ: หมายเลขกลุ่มถูก join กลับเข้าเป็นตัวแปรหนึ่งของตารางรายเรซ

การจัดกลุ่มทำให้โมเดลได้คำอธิบายของสนามแทนรหัสสนาม และอธิบายได้ว่าสนามในกลุ่มเดียวกันเหมือนกันเพราะอะไร

5 · ตัวแบบ Models

ไฟล์ทำอะไร
code/01_data-prep-and-modeling.Rmd สร้างตัวแปรทั้งหมด รัน Random Forest และสาธิตการจับคู่ผลทำนายทั้งสนามเข้ากับโควตาโพเดียม / ได้คะแนน / ไม่ได้คะแนน (3 + 7 + 10)
code/02_modeling-v1.R เปรียบเทียบ Random Forest กับ XGBoost ด้วย cross-validation แบบ expanding window (train ก่อนปี 2024, test ทุกรอบของปี 2024) พร้อมเมตริกราย fold
code/03_modeling-v2-quota-and-strict.R เวอร์ชัน 2: รวมสัญชาติที่มีข้อมูลน้อยเป็นกลุ่ม Other เพิ่มโหมด strict ของการจัดโควตา ปรับไฮเปอร์พารามิเตอร์ด้วย grid search และคำนวณ SHAP

สคริปต์ทั้งสองอ่าน data/final_table_with_cluster.csv จากรีโป และเรียกใช้ xgb.train / xgb.DMatrix

6 · การวัดผล Evaluation

การแบ่งข้อมูล: ฝึกด้วยปี 2019–2023 และทดสอบกับทุกรอบของฤดูกาล 2024 การแบ่งเป็นไปตามลำดับเวลาเพราะเป็นงานพยากรณ์ไปข้างหน้า หากสุ่มแบ่ง โมเดลจะเห็นเรซที่เกิดหลังเรซที่กำลังทำนาย ทำให้ค่าที่วัดได้สูงเกินจริง

Cross-validation: แบบ expanding window ตามลำดับเรซ จำนวน 4 fold โดยแต่ละ fold ใช้ข้อมูลเรซก่อนหน้าทั้งหมดในการฝึก

ผลที่รายงาน: XGBoost ให้ผลดีที่สุดบนชุดทดสอบฤดูกาล 2024 (ตัวเลขตามที่แสดงด้านบน) ผลของ SHAP จัดให้ตำแหน่งออกสตาร์ทมีอิทธิพลสูงสุด ตามด้วยศักยภาพและผลงานย้อนหลังของทีมและนักขับ ส่วนประเภทสนามและสภาพอากาศมีอิทธิพลต่ำ

7 · ข้อจำกัด Limitations

  1. ขนาดข้อมูล: 2,559 race entries จาก 6 ฤดูกาล
  2. ใช้เฉพาะข้อมูลก่อนแข่ง: กลยุทธ์ระหว่างการแข่ง การเลือกยางระหว่างเรซ และการจำลองสถานการณ์สดอยู่นอกขอบเขตของงานนี้โดยตั้งใจ
  3. การเลือกจำนวนกลุ่ม: รายงานใช้ 5 กลุ่ม ขณะที่โค้ดสำรวจบางส่วนตัดที่ 3 กลุ่ม การเลือกของรายงานอ้างอิงดัชนีคุณภาพการแบ่งกลุ่ม
  4. ขอบเขตการทดสอบ: ชุดทดสอบมีเฉพาะฤดูกาล 2024 ยังไม่มีการทดสอบกับฤดูกาลถัดไป
