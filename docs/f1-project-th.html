🏆 รางวัลที่ 1 — โปสเตอร์นำเสนอโปรเจกต์จบ ป.ตรี

โปรเจกต์นี้ได้รางวัลที่ 1 จากการนำเสนอโปสเตอร์ประกอบโปรเจกต์จบ (ดู โปสเตอร์ PDF ฉบับเต็ม)

ROC-AUC 0.883 Accuracy 0.810 Precision 0.775 Recall 0.875 F1-Score 0.822 Test set ฤดูกาล 2024

ตัวเลขด้านบนคือของ XGBoost ตาม รายงานฉบับจบ (PDF ภาษาไทย) — ดู projects/f1-driver-points-prediction/report/ สคริปต์ R ใน repo (02_modeling-v1.R, 03_modeling-v2-quota-and-strict.R) เป็นโค้ดที่ใช้รันก่อนหน้านั้น เมตริกถูกคำนวณต่อรอบแข่ง (accuracy, F1 macro/weighted, precision/recall macro)

1 · โจทย์ ทำนายอะไร หน่วยวิเคราะห์คืออะไร ใครใช้เพื่ออะไร

เป้าหมาย: ทำนายว่านักขับหนึ่งคนในหนึ่งเรซจะจบอยู่กลุ่มใด — podium (อันดับ 1–3) / scoring (4–10 ซึ่งได้คะแนน) / no_point (อันดับ 11 ขึ้นไป) และมุมมอง binary “เข้า Top-10 หรือไม่” เทียบเท่าได้

หน่วยวิเคราะห์: หนึ่งแถว = ผลของนักขับหนึ่งคนในหนึ่งเรซ (race entry) — ปี 2019–2024 รวม 2,559 race entries

ใครใช้เพื่ออะไร: สร้างภาพความน่าจะเป็น "ก่อนสุดสัปดาห์แข่ง" จากข้อมูลที่มีก่อนแข่งเท่านั้น (ประวัตินักขับ/ทีม, ตำแหน่ง grid, ลักษณะสนาม, อากาศ) — เพิ่มอีกมุมคือ assignment ตามโควตา: ทำนายทั้งเรซแล้วจัดกลุ่มตามข้อจำกัดจริงของ F1 ที่ podium มีแค่ 3 ที่ + scoring อีก 7 ที่ (รวม 10 ที่ได้คะแนน)

ไฟล์ที่อ้างอิง: code/01_data-prep-and-modeling.Rmd (ตัวแปร score_group)

2 · ข้อมูล แหล่ง 4 แหล่ง · ขนาด · วิธีเชื่อมอากาศเข้ากับเรซ

แหล่งข้อมูลใช้ทำอะไร
Ergast F1 API ผลแข่ง, ตำแหน่ง grid, pit stop, lap times, standings, status (DNF หรือไม่) — เก็บเป็น zip ใน repo ที่ data/ergast-f1-data.zip
Open-Meteo อุณหภูมิ / ฝน / ลม รายชั่วโมง (UTC) รายสนาม — ดึงแบบหน้าต่าง ±3 วันรอบเรซ เก็บไฟล์ตัวอย่างไว้บางเรซ และมีสคริปต์ rebuild ครบทุกเรซ
Pirelli Motorsport ลักษณะสนามเชิงวิศวฯ: tyre stress, lateral load, grip, downforce, ความยาวสนาม, จำนวนโค้ง — กรองเหลือ 129 สนาม–เรซ (แล้วตัด 1 ที่ข้อมูลหาย) เหลือ 128 สนาม สำหรับ clustering
Race scheduleรอบแข่ง + เวลาแข่ง (ใช้คำนวณหน้าต่างเวลาแข่ง)

วิธีเชื่อมอากาศเข้ากับเรซ: ระยะเวลา "แข่งจริง" ของแต่ละเรซคำนวณจาก total milliseconds ที่คนจบอันดับหนึ่งวิ่ง (จาก lap_times) นับถึงเวลาเริ่มแข่ง (วันแข่ง + เวลาท้องถิ่น) — จากนั้นหาค่าเฉลี่ยอากาศในหน้าต่างเวลาแข่งจริง — ไม่ได้ใช้ค่าเฉลี่ยทั้งวัน

Raw ตัวใหญ่ไม่ได้ commit — README.md ของโปรเจกต์ระบุแหล่งดาวน์โหลด + วิธี regenerate ด้วย code/build_weather_circuit.R (สคริปต์เรียก network ราว 3 นาที) (โค้ดหลักใช้ปี 2024 รอบเดียวในโหมด demo)

3 · ฟีเจอร์ + data-leakage สร้างตัวแปรอะไร ข้อมูลต้องเกิด "ก่อนแข่ง" เท่านั้น

ฟีเจอร์ตรรกะ — ข้อมูลนี้มี "ก่อนแข่ง" ตั้งแต่เมื่อไหร่?
Ageอายุจากวันเกิดถึงวันแข่ง
Driver_Experience จำนวนเรซที่นักขับแข่งมาก่อนหน้าเรซนี้ (row_number − 1 ต่อ driver, เรียงตามปี)
Driver_Podium จำนวน podium สะสม ก่อนหน้าของเรซนี้ — lag(cumsum(positionOrder in 1:3))
Prev_Total_Points คะแนนสะสมก่อนหน้า (lag cumsum คะแนน — นับเฉพาะเรซก่อนหน้า)
Constructor_Wins จำนวนชัยชนะสะสมของทีม ก่อนเรซนี้
Constructor_DNF_Score จำนวน DNF สะสมของทีม ในข้อมูลก่อนเรซนี้
avg_temperature / avg_rain / avg_wind_speed ค่าเฉลี่ยอากาศในหน้าต่างเวลาแข่งจริงของเรซนั้น
clusterหมายเลขกลุ่มของสนาม ที่ได้จากการ clustering (หัวข้อ 4)
gridตำแหน่งออกตัว — ใช้ใน pipeline หลัก (final_table_with_cluster.csv ใน data/ มีคอลัมน์ grid) — ใน Rmd 01 โหมด demo ตัด grid ทิ้ง แต่ในไฟล์ v1/v2 ใช้ มี grid อยู่ เจาะจงต้องตอบเอง
❗ จุดที่ interviewer มักพุ่ง (data-leakage ธรรมชาติ) — ต้องตอบให้ชัด:
1) ประวัติ cumsum ต้อง lag ก่อนเรซปัจจุบัน เสมอ เพื่อไม่ให้ค่าของเรซนี้รั่วเข้าไป
2) ตัวแปรประเมินประสิทธิภาพ (เช่น Overtake_Rate) ต้องคิดเฉพาะเรซก่อนหน้า เพราะเป็นข้อมูลที่มีหลังแข่ง — ไม่ใช่ก่อนเรซปัจจุบัน
3) DNF_flag ใช้ข้อมูล status (ผลหลังแข่ง) ผ่าน is_finished — ใช้ได้เพราะถูกใช้เป็นข้อมูล "ภายหลังของเรซก่อนหน้า" ตาม lag
ต้องตอบเองละเอียดใน exam-f1-th.html (เวอร์ชันไทย) หรือ exam-f1.html หมวด B — อ่านโค้ดจริงได้ที่ code/01_…Rmd

4 · คลัสเตอร์สนาม clustering แบบ unsupervised — 128 สนาม

  1. เก็บสนามต่อ (circuit, ปี, รอบ): รวมตัวแปร Pirelli (จำนวนโค้ง, ระยะ, ความยาว, tyre stress, lateral, downforce, asphalt grip, asphalt abrasion) เพิ่ม ตัวแปร "การแข่งจริง" ที่คำนวณจาก Ergast: Overtake_Rate, Race_DNF_Rate
  2. ประเมินความเหมาะสม: KMO / correlation ระหว่างตัวแปร เช่น KMO(cor(clus_dat)); พิจารณาเหตุผลเชิงมิติของตัวแปรแต่ละชุด
  3. ลดมิติข้อมูล: PCA — เลือก 5 องค์ประกอบ (พิจารณาที่ cumsum ของ explained variance เพียงพอ)
  4. Clustering: daisy(..., metric = "gower") → hclust(..., method = "complete") → เลือกจำนวนกลุ่ม ด้วยดัชนีคุณภาพการแบ่งกลุ่ม จาก plot_idx(Hvalid(...)) (ครอบคลุม silhouette และดัชนีอื่น) พร้อมอธิบายเหตุผลที่เลือกจำนวนกลุ่ม
    สิ่งที่ต้องตอบให้เจาะจง: รายงานจบใช้ 5 กลุ่ม แต่โค้ดตัวอย่างบางส่วน (cutree(hc_com, 3)) ใช้ 3 — ต้องอธิบายได้ว่าเลือกจากดัชนีคุณภาพการแบ่งกลุ่มอย่างไร เหตุผลเจาะจง ไม่ใช่เลือกลอยๆ
  5. เก็บทำใช้ต่อ: ตัวแปร cluster จากกลุ่มถูกสร้างแล้ว join กลับเข้าตารางรายเรซ (ให้เป็น feature ของโมเดล)

เป้าหมายการ cluster = ทำให้ "สนาม" เป็นตัวแปรที่มีสาระเข้าโมเดล แทนที่จะใช้ id สนามแบบตรงๆ (จัดได้ว่าสนามไหนอยู่กลุ่มเดียวกัน จนอธิบายได้ว่าเหมือนกันเพราะอะไร)

5 · โมเดล + การตีความผล RF + XGBoost + แปลงผลเป็นโควตา

ไฟล์ทำอะไร
code/01_…Rmd รวม feature ทั้งหมด → RF demo (ntree=1000, mtry=5) → ทำนาย 1 เรซแล้วแปลงเป็น assignment ตามโควตา (3 podium + 7 scoring + 10 no_point)
code/02_modeling-v1.R v1 — ทดสอบ RF + XGBoost โดย Expanding-window CV: train ปี <2024, test ปี 2024 (รอบ 1–20) · เทียบ RF (500 ต้น) กับ XGBoost (multi:softmax, 3 กลุ่ม) ทั้ง 2019–2023 CV + ทดใน 2024 · รายงาน metrics ครบต่อ fold (accuracy, F1 macro/weighted, prec/rec) พร้อม align_matrix ของ xgboost ในช่วงเทียบคอลัมน์
code/03_…strict.R v2 — เพิ่ม nationality bucketing (จับ Nationality ที่มีข้อมูลน้อยไป "Other"), เพิ่ม โหมด strict ของ quota assignment พร้อม train() กับ time-series control + Grid Search ของ hyperparameters และ SHAP/Feature importance ตามโค้ดจริง

ทั้งสองไฟล์ v1/v2 ใช้ data/final_table_with_cluster.csv ที่ commit ไว้ โค้ดใช้ xgboost API xgb.train / xgb.DMatrix ที่ทำงานได้กับทั้ง xgboost รุ่น 1.7 และ 3.x — และทั้งคู่จบด้วยการแปลงผลเป็น quota 3+7+10 เสมอ

6 · วัดผล โครงสร้าง split + การตีความ CV

Split: train = ชุด 2019–2023 (ปลอด 2024) · test = ทุกการแข่งของปี 2024 (รอบ 1–20) — เรียงตามเวลา เพราะเป็นโจทย์ทำนายไปข้างหน้าในเวลาจริง — ถ้า random split โมเดลจะมีข้อมูลหลังเรซที่ต้องทำนาย ทำให้เมตริกสูงเกินจริง

CV ประสิทธิภาพ: fold ตามลำดับเรซ แบบ expanding window — fold หลังใช้ข้อมูลเรซก่อนหน้าทั้งหมด

ผลที่รายงาน (จาก PDF report): XGBoost ชนะ RF ในทุก CV (ROC-AUC ~0.840 vs ~0.820 per fold) จาก report ใช้ test ปี 2024 แล้วได้ตัวเลข 5 เมตริกเหมือนแบบ: ROC-AUC 0.883 · Accuracy 0.810 · Precision 0.775 · Recall 0.875 · F1 0.822; feature สำคัญตาม SHAP — grid position อันดับ 1 ตามด้วยประสิทธิภาพทีม/นักขับ

สำหรับ v1 / v2: โค้ด print metrics ต่อ fold + confusion matrix ต่อ fold ทาง PDF รวมผลสุดท้าย แล้วเลือกโมเดลที่ผลดีสุด

7 · ข้อจำกัดจริง ของจริง ไม่ gloss ไม่เปิดเฉย

  1. คุณภาพตั้งต้นการฝึก: ใช้เฉพาะฟีเจอร์ pre-race ที่เป็นจริงก่อนแข่ง — ข้อมูล (ปี 2019–2024, รวม 2,559 race entries) เป็นจำนวนจำกัด ต้องบอกได้ว่าถ้าทำจริงจะขยายข้อมูลเพิ่มอย่างไร
  2. ไม่ รวมข้อมูล strategy/sim เชิง current — ใช้เฉพาะสิ่งที่มีจริงก่อนแข่ง
  3. เลือก k ของคลัสเตอร์: รายงานใช้ 5 กลุ่ม โค้ดตัวอย่างอาจได้ 3 — ต้องอธิบายเหตุผลได้ว่าทำไม 5 ไม่ใช่ 3
  4. ขอบเขต test: test set คือปี 2024 เท่านั้น — ยังไม่ได้ทดสอบทำนายฤดูกาลถัดไปจริง และเรซหนึ่งอาจมีสถานการณ์ปลายเปิดที่โมเดลคาดไม่ถึง
❗ จะตอบ "หน้าตัวจริง" ได้ต้องฝึกผ่านชุดข้อสอบ (เช่น exam-f1-th.html): อธิบายได้ว่าคอลัมน์จริงและค่าที่คำนวณต่างจากตาราง demo อย่างไร รวมถึงอธิบายได้ว่าจะจัดโควตา (3 podium + 7 scoring + 10 no_point) อย่างไรเมื่อโอกาสยังไม่ชัดเจน
อ่านแล้วพิจารณารายละเอียดที่ exam-f1-th.html (ไทย) — หน้าจอ 8 หมวด ~28 ข้อ
